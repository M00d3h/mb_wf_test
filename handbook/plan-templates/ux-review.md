# UX review

**Use for:** reviewing the built product for usability, after a round of features lands.
**Usually needs:** something built with a UI. UX conventions, and a prototype if there was one.
**Produces:** `work/audits/YYYY-MM-DD-ux.md`, issues, updated conventions

## Steps

- [ ] Review in a fresh session as someone using it daily. Each entity has the operations people need. Errors are actionable and forms keep their data. Loaded, empty, loading and error states exist. Destructive actions are confirmed. No dead ends in navigation. Similar features behave alike. The UX conventions are followed. Severity depends on context: a missing spinner on a page that loads instantly is low. Record gaps even if already tracked, with a link.
- [ ] If there was a prototype, compare the look and feel: theme, layout, spacing, interaction. For each difference, say whether it was intentional, and whether the built version is better.
- [ ] Update the UX conventions where practice proved better than what's written.
- [ ] File issues, and propose work items. The engineer decides.
- [ ] Close.
