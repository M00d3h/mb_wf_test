# Lens review

**Use for:** reviewing the whole codebase through one [lens](../lenses.md): security, performance, data, operability, and so on. Rotate through them, least recently used first.
**Usually needs:** nothing.
**Produces:** `work/audits/YYYY-MM-DD-<lens>.md`, issues

## Steps

- [ ] Pick the lens and say why. Read the standards it relates to.
- [ ] Review in a fresh session through that lens only. Stay in its lane. Three findings that matter beat fifteen trivial ones. Check against `work/backlog/` and `work/issues/` so nothing is filed twice.
- [ ] File each finding as an issue, and write the report.
- [ ] The engineer decides which become work items. Small fixes can be added to this plan instead.
- [ ] Close.
